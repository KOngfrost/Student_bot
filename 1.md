Сначала разберу репозиторий по исходникам — структуру, зависимости, запуск, уязвимые места и фактическую готовность к развёртыванию. Затем дам пошаговую установку с нуля; для выполнения именно на сервере позже понадобятся его ОС и способ доступа, но пароли/SSH-ключи сюда присылать не нужно.

Провёл статический разбор ветки `master` репозитория Student_bot. Это Python-проект VK-бота с PostgreSQL, Alembic-миграциями и веб-панелью администратора.

## Что сделано хорошо

- **Понятная архитектура:** отдельно выделены `bots`, `core`, `web`, миграции Alembic и скрипты обслуживания.
- **Docker Compose уже подготовлен:** PostgreSQL, VK-бот и веб-панель запускаются отдельными сервисами.
- **Данные сохраняются** в Docker volume PostgreSQL.
- **Есть автоматические миграции** при запуске бота.
- **Используется асинхронный стек:** `asyncpg`, SQLAlchemy Async, FastAPI.
- **Предусмотрены retry-механизмы** для подключения к PostgreSQL и VK Long Poll.
- **Токены и пароли вынесены в `.env`**, а контейнер бота запускается не от root-пользователя.
- Есть основа для заявок, администраторов, FAQ, базы знаний, мероприятий, подписок, регистрации и логов.

Docker-конфигурация действительно поднимает три сервиса: `db`, `bot` и `web-admin`, а база защищена от запуска бота до прохождения healthcheck.

## Основные минусы

### 1. Функциональность пока в основном заготовка

Кнопки «Жилбыт», «Культмасс», «Информ», «Корпоративный» и «Анонимное обращение» пока возвращают информационные заглушки. Реальных анкет, создания обращений, обработки заявок и ответов студентам в VK нет.

Это подтверждает и техническое задание проекта: в нём прямо указано, что полноценные сценарии отделов, FAQ, мероприятия, анонимные обращения и администрирование заявок ещё не реализованы.

### 2. Веб-панель небезопасна для прямой публикации в интернет

- Порт `8000` опубликован наружу без HTTPS.
- Нет Nginx или другого reverse proxy.
- Пароль сравнивается как обычная строка, а не через bcrypt/argon2.
- Нет CSRF-защиты для HTML-форм.
- Удаление некоторых объектов выполняется через `GET`, что небезопасно.
- Авторизация веб-панели фактически даёт пользователю полный доступ; разграничение ролей не реализовано.
- При отсутствии `SESSION_SECRET_KEY` генерируется временный секрет, из-за чего сессии сбрасываются после перезапуска.

Проверка авторизации в коде есть, но она основана только на единой паре `WEB_ADMIN_USERNAME`/`WEB_ADMIN_PASSWORD` из `.env`.

### 3. Документация местами противоречит коду

`WEB_ADMIN_GUIDE.md` всё ещё описывает логин `admin` и пароль `admin123`, а текущий код таких значений по умолчанию не содержит. На чистом сервере вход будет закрыт, пока явно не задать переменные в `.env`.

В README также встречается ошибочное значение `DB_PORT=542`, тогда как рабочий PostgreSQL-порт — `5432`. Для установки будем использовать `.env.example`, а не устаревшие фрагменты README.

### 4. Не хватает production-части

- Нет автоматического расписания резервных копий.
- Нет мониторинга и уведомлений о падении контейнеров.
- Нет ротации Docker-логов.
- Нет healthcheck для самого бота и веб-панели.
- Нет CI с тестами и линтерами.
- Нет полноценного набора тестов.
- Веб-панель при старте дополнительно вызывает `create_all`, хотя схема должна управляться миграциями.
- Весь проект пока рассчитан скорее на небольшой внутренний MVP, чем на публичную эксплуатацию.

## Как будем устанавливать с нуля

Рекомендую такую схему:

1. Чистый VPS на Ubuntu 24.04 LTS.
2. Установка Docker Engine и Docker Compose Plugin.
3. Клонирование репозитория в `/opt/student_bot`.
4. Создание защищённого `.env`.
5. Настройка VK-сообщества и Long Poll API.
6. Запуск PostgreSQL, бота и веб-панели.
7. Создание первого суперадминистратора.
8. Проверка логов и тестовое сообщение боту.
9. Закрытие порта веб-панели через SSH-туннель или Tailscale.
10. Настройка ежедневных резервных копий.

На чистом сервере базовая команда запуска будет такой:

```bash
git clone https://github.com/KOngfrost/Student_bot.git /opt/student_bot
cd /opt/student_bot

cp .env.example .env
chmod 600 .env

# После заполнения .env
docker compose up -d --build
docker compose ps
docker compose logs --tail 100 bot
```

Для первого запуска понадобятся только:

- токен сообщества VK;
- VK ID администратора;
- VK ID получателя отчётов;
- пароль PostgreSQL;
- логин и пароль веб-панели;
- случайный `SESSION_SECRET_KEY`.

Секреты и SSH-пароль сюда присылать не нужно — их зададим непосредственно на сервере. Сначала уточним ОС, чтобы команды установки Docker были точными.
