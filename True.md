- __Бизнес-логика не реализована (главный минус)__

  - Все разделы меню («Жилбыт», «Культмасс», «Информ», «Корпоративный», «Анонимное обращение») — заглушки с текстом «форма готовится».
  - «Мои заявки» — заглушка, всегда отвечает «Активных заявок пока нет».
  - Нет создания заявок, обработки администратором, смены статусов, FAQ-дерева, мероприятий, подписок, рассылок.

- __Alembic настроен, но не используется__

  - `alembic/versions/` пуст — нет ни одной миграции.
  - Таблицы создаются через `Base.metadata.create_all` в рантайме, что противоречит заявленному в ТЗ использованию Alembic и опасно при эволюции схемы (нет версионирования, нет откатов).

- __Проблемы с отчётностью__

  - `build_users_report` — отчёт содержит только VK ID и дату, а по ТЗ нужны сводка по отделам, детализация заявок, анонимные обращения, процент выполнения.
  - Отчёт отправляется только в VK, email-рассылка из ТЗ не реализована.
  - Планировщик использует `threading.Thread` + `asyncio.run()` в каждом цикле — создаёт новый event loop на каждую итерацию, что хрупко и может конфликтовать с общим циклом бота. Лучше использовать единый asyncio-планировщик (APScheduler или asyncio task).

- __Архитектурные огрехи__

  - `core/bot_core.py` содержит `main_menu_keyboard()` — генерация клавиатуры VK в core-слое, хотя клавиатуры уже вынесены в `bots/vk/keyboards.py`. Дублирование и нарушение разделения.
  - `BotCore.get_or_create_user` кэширует только `vk_id` в памяти без инвалидации — при изменении данных пользователя (ФИО, общежитие) кэш устареет.
  - `User` в `bot_core.py` — дубликат модели `UserModel` с одним полем; это избыточная прослойка.
  - `is_admin` в `BotCore` проверяет только `ADMIN_VK_IDS` из env, игнорируя таблицу `admins` и роли `admin`/`superadmin` из модели.

- __Безопасность__

  - Нет логирования действий (`Log` модель есть, но нигде не используется).
  - Нет rate-limiting и защиты от спама.
  - `VK_REPORT_ADMIN_ID` и `ADMIN_VK_IDS` — только env-переменные, нет управления через БД/веб-панель (по ТЗ должна быть веб-админка).

- __Отсутствие тестов__

  - В проекте нет ни одного теста (unit/integration). Для бота с БД и внешним API это существенный риск.

- __Мелочи__

  - `bots/telegram/` — пустая папка (задел, но не реализация).
  - `requirements.txt` без версий (кроме SQLAlchemy>=2.0) — невоспроизводимая сборка.
  - `main.py` ловит `VKAPIError` только вокруг `run()`, но `run_vk_polling` перехватывает лишь сетевые ошибки — `VKAPIError` (например, истёкший токен) уронит процесс без понятного сообщения.
  - `scripts/check_db.py` дублирует логику `ensure_database_exists` из `core/database.py`.
  - Нет форматтера/линтера (black/ruff) в конфигурации.
